# CrateClean: notes for AI coding agents

CrateClean is a desktop app for macOS, with Windows to follow, written in Python with a Qt interface (PySide6) and mutagen as the tag engine. It cleans junk (download-site URLs, promo text) out of DJ music tags and finds missing cover art, without breaking a Rekordbox library. Every change is previewed, backed up, verified after writing and can be undone.

## Hard rules

- **Edit tags only.** Never rename, move or delete audio files, and never create files inside the user's music folders (no temp files, no sidecars, no images). Rekordbox links tracks by path, so a moved file loses its cues, grids and playlists.
- **Never touch BPM, key, rating, cue or DJ-software fields**: TBPM, TKEY, POPM, Serato and Rekordbox GEOB/PRIV frames, and their FLAC and MP4 equivalents. Never touch existing artwork unless the user approved replacing low-res art.
- **Nothing is written without the user's approval.** Every change is shown in a preview first, and nothing is written until the user clicks Apply.
- **Every write goes through the pipeline** in `crateclean.engine.write`: backup → write → verify → restore on failure. Never save a mutagen object anywhere else, including in scripts and tests that touch real files.
- **Keep each file's tag format.** ID3v2.3 stays v2.3, and multi-value frames keep their original separator.
- **Never write to Rekordbox's database or XML.**
- **Network access goes only to MusicBrainz, Cover Art Archive and Discogs**, through the rate-limited clients in `crateclean.apis`. No telemetry, analytics, crash reporting or update checks.
- **`engine`, `match`, `apis` and `store` never import Qt.** The UI never reads or writes files or makes requests on the GUI thread.
- **Never ship or commit a Discogs consumer key or secret.** Users paste their own personal token, which is stored with `keyring`.
- **Never commit real music.** Test fixtures are generated by a script, from silence or tones.
- **The project is GPL-3.0-or-later** because mutagen is GPL. Any new dependency must have a compatible licence.

## Git workflow

- **Never commit to `main`.** It's protected on GitHub: no direct pushes or force-pushes, and merging needs a pull request with the CI checks passing.
- Start every change on a new branch from an up-to-date `main` (`fix/…`, `feature/…`, `docs/…`, `ci/…`), push it, and open a pull request with the template filled in.
- Pull requests are squash-merged and the branch is deleted automatically. After a merge, run `git switch main && git pull` before starting the next branch.
- Releases go through a `release/vX.Y.Z` pull request. Tag the merge commit after it lands.

## Build and test gotchas

Add to this as they're found. Each entry: the symptom, the cause, and what to do instead.

- Run everything through uv: `uv sync` once, then `uv run pytest`, `uv run ruff format`, `uv run pyright`. Don't install packages with `pip` into the system Python.
- The tests generate audio fixtures with ffmpeg the first time they run (`tests/fixtures/make_fixtures.py`, called from `conftest.py`).
- mutagen converts ID3v2.3 frames to their v2.4 form in memory when it loads a file, unless told not to. Saving with `v2_version=3` converts them back, but not always exactly. The round-trip tests guard this; don't change how files are loaded or saved without them passing.
- Windows comes last ([ADR 0010](docs/adr/0010-macos-first.md)), and the maintainer has no Windows machine. Until the Windows milestone, CI runs on macOS only, but write code that will work on Windows: `pathlib` for paths, Python scripts rather than shell scripts, and nothing macOS-specific outside `crateclean.ui.platform`. CONTRIBUTING.md's "Testing on Windows" is the plan for when it starts.
- Store app data with `QStandardPaths.AppLocalDataLocation`, not `AppDataLocation`. On Windows the latter is the roaming profile, which some networks sync between machines, and backups can be gigabytes.
- Before a release, test the PyInstaller build, not just `uv run`. PyInstaller can miss modules and data files that only load at runtime.
